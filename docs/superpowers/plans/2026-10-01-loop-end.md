# 闭环末端：Report 与 KB 导出（S1 + S2）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在工作台上把闭环末端接上——**生成 Report**（覆盖式查看器，可复制/另存为 `.md`）与**导出到知识库**（诚实反馈：端点已接收 ≠ 已收录）。

**Architecture:** main 侧新增两条会话命令 `report(recordId, detailLevel)` / `export(recordId, object)`（分别转发 `report.generate_request/result` 与 `record.export_request/result`），以及一条 `save_text`（`dialog.showSaveDialog` + 写文件，落点是一个可单测的纯 helper）。renderer 侧新增 `ReportViewer` 覆盖层，并在 `Workbench` 头部加动作区，由 `app.tsx` 持有报告/导出结果的状态。

**Tech Stack:** Electron + electron-vite · React + TS（strict）· Vitest（node + jsdom/RTL）· Playwright Electron · pnpm workspace

**Spec:** `docs/superpowers/specs/2026-10-01-workbench-and-loop-closeout-design.md`（§5 Report、§6 KB 导出、§10 IPC、§12 测试、§15 拆分）。**本计划是 P-loop-end**；S0/S3（工作台与取消）已在 `master`，S5/S4（附件与 blob、手工动作 `details`）是 **P-attachments**。

## Global Constraints

- **renderer 不 import `@adt/server`、不碰 Node**；`contextIsolation: true` / `nodeIntegration: false` 不变。
- **报告内容只来自 Server**：客户端只**发起请求并展示**，**不本地拼凑、不缓存伪造**（`CLIENT_SPEC` §3 第 12 条、`REPORT_SPEC` §6）；每次点击都重新请求。
- **导出诚实**：`ok` 只表示"**端点已接收（2xx）**"，**不表示已被收录**（`ADR-005` §4）；未配置端点 → `export_unavailable`；**不追踪审核状态**。
- **Markdown 呈现**：本切片用**等宽原文**（`<pre>`）呈现 Server 返回的 markdown，**不引入 markdown 依赖**（YAGNI + 避免 XSS 面）；格式化渲染归后续。
- **不引入新依赖、不引入 CSS 框架**（renderer 保持 DOM + `className`）。
- 编辑文件用 `edit` 工具（仓库 **LF**）；**不 push**。
- 验证口径：`pnpm -r --if-present test`（**串行**）+ `pnpm -r --if-present typecheck` + `pnpm -C packages/client-electron build` + 桌面冒烟。
- 本计划**刻意不做**：附件与 blob（**P-attachments**）、报告格式化渲染、导出审核状态回读、报告持久化。

## Review Focus

以下失败模式是本 spec 隐含、但默认测试不会覆盖的；**每条都必须在对应任务里有测试**：

1. **报告失败不显示半成品**：`report.generate_result.status="failed"`（或 `protocol.error`）时，查看器**显示错误**、不显示任何正文（`REPORT_SPEC` §6）。见 Task 1 / Task 4。
2. **导出"已接收"不被说成"已收录"**：成功文案必须明确"端点已接收 ≠ 已被收录"，`export_unavailable` 有独立文案。见 Task 2 / Task 4。
3. **生成报告不改变 Record、不触发新诊断**：客户端只发一次 `report.generate_request`，不附带任何写操作；同一 Record 可重复生成（`FR-19`）。见 Task 1。
4. **往期（history）与 live 都能用**：只要该会话已有 `recordId`，报告/导出按钮可用；无 `recordId`（进行中）时不可用。见 Task 4。
5. **另存为真的落盘或明确失败**：保存对话框取消 → `{saved:false}`，UI 不谎报成功。见 Task 3 / Task 4。

**Interfaces:**
- Produces:
```ts
// ReportViewer：覆盖式查看器（presentational）
export interface ReportViewerProps {
  markdown: string;
  onCopy(): void;
  onSave(): void;
  onClose(): void;
}
// 根节点 data-testid="report-viewer"。
```
- `Workbench` 新增 props（在现有 `items/cancelling/canCancel/onCancel` 之外）：
```ts
{
  recordId: string | null;               // 该会话的 Record（无则报告/导出不可用）
  reportReady: boolean;                  // 本会话是否已成功生成过报告（决定能否导出 object=report）
  onGenerateReport(detailLevel: "summary" | "full"): void;
  onExport(object: "record" | "report"): void;
}
```
  头部动作区（`recordId !== null` 时）加：**生成报告**（一个 `<select>` 选 `完整`/`摘要` + 按钮）与**导出到知识库**（一个 `<select>` 选 `Record`/`Report`，`Report` 在 `!reportReady` 时禁用 + 按钮）。无 `recordId` 时这两个动作**不出现**。
- `app.tsx` 新增状态与处理：
  - `report: { markdown: string } | null`（打开查看器）、`reportError: string | null`、`reportReady: Record<recordId, true>`（简单标志：`Set<string>`）。
  - `handleGenerateReport(detailLevel)`：`client.report(selectedRecordId, detailLevel)` → `ok` 存 markdown 并标记 `reportReady`；否则 `setReportError(...)` 并打开查看器显示错误（**不显示正文**）。
  - `handleExport(object)`：`client.export(selectedRecordId, object)` → 把结果（含 `ok`/`errorCode`）放入一条 `role="status"` 提示（文案见 §6 诚实措辞）。
  - `handleSaveReport()`：`client.saveText("report.md", markdown)` → `saved` 才提示成功，取消则不谎报。
  - `selectedRecordId` = 当前选中会话的 `recordId`（live 用 `summary.recordId`，history 用 `conversation.recordId`）。
