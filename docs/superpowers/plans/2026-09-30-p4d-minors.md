## 决议（定稿于对话）

| # | 原延后项 | 决议 |
|---|---|---|
| N1 | `KB_MAX_RETRIES` 无上界（`LLM_MAX_RETRIES` 同款脚枪、同款重复解析代码） | **修**：抽一个共享的有界解析器，**两个都加上限 10**；超上限**回落默认值**（不截断），并**告警** |
| N2 | `object=report` 固定 `detail_level="full"`，无法请求 `summary` | **不改，记为有意限制**：`summary` 的唯一场景（`REPORT_SPEC` §3"口头汇报前快速看一眼"）与"沉淀到知识库供复用"是相反诉求；`REPORT_SPEC` §3 自己就以"不需要事后靠回忆补记"为理由把 `full` 设为默认。**重开信号**：出现真实的"只沉淀结论、不带过程"的脱敏/收敛需求——那是数据治理规则，不是 `detail_level` 旋钮 |
| N3 | 导出路径里 `generateReport` 的失败分支当前不可达 | **保留为护栏**：`ReportResult` 确实声明了失败态，诚实处理它是对的；**不计入已覆盖行为** |
| N4 | `buildDeposit` 允许 `object:"report"` 却不给 `report`（会投 `content:null`） | **修**：入参改**判别联合**（编译期堵死）+ 运行时 `TypeError`（挡住无类型的 JS 调用者，该函数是包的公开导出） |
| N5 | 协议测试没有断言 `object=record` 时 `spec_versions` 存在 | **修**：补断言，且断言它**等于 Record 自己的** `spec_versions`（ADR-005 §3） |

**顺带**：`KB_TIMEOUT_MS` 仍走同一个解析器但**故意不设上限**——理由是"超上限时回落到默认"对一个合理的大超时是更坏的意外（把 120s 悄悄变成 10s），而它的代价（最坏耗时逼近心跳判死阈值）已由启动告警覆盖。该理由写在 `env.ts` 与 `kb/config.ts` 的注释里。
